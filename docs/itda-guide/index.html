Overview

itda는 무엇인가요?

사내 서버 3대로 이루어진 컨테이너 클러스터에 내 서비스를 올리고, 바로 사내 도메인으로 공개하는 플랫폼입니다.

🚀

배포

이미지·Git 저장소·소스 압축 파일·DB까지. 배포하면 itda.rgrg.im/서비스명/ 주소가 바로 생깁니다.

🤖

MCP 연결

AI 개발 도구에서 "배포해줘", "왜 죽었는지 봐줘"라고 말하면 itda가 대신 실행합니다. 오늘의 핵심입니다.

💾

운영

영구 저장소, 시크릿 주입, 로그·컨테이너 진단, 삭제 방지, 다른 사용자와 공유까지.

구성

서버 3대(master · node-b · node-c) · 내장 Docker registry 20.20.6.248:5000 · 관리 콘솔 /admin

로그인

회사 Google 계정(@parametacorp.com)만 사용합니다. 처음 로그인하면 계정이 자동으로 만들어집니다.

MCP

MCP로 배포한다는 것

MCP(Model Context Protocol)는 AI 도구가 외부 시스템의 기능을 직접 호출하게 해 주는 표준입니다. itda는 18개 도구를 MCP로 제공합니다.

이 프로젝트 빌드해서 itda에 my-api로 올려줘
get_registry_info → docker push → deploy_image내부 registry에 push하고 my-api를 배포했습니다.
주소: https://itda.rgrg.im/my-api/
자꾸 재시작되는데 왜 그래?
inspect_containers · get_logs메모리 부족(OOM)으로 종료됐습니다. 메모리 제한을 512m로 올려 다시 배포할까요?

✅ 내 서비스만

토큰은 발급한 계정의 서비스만 조회·수정합니다. 관리자 토큰도 예외가 없습니다.

✅ 포털과 같은 규칙

MCP 요청도 포털과 같은 권한 검사·감사 로그를 거칩니다.

✅ 위험한 작업은 확인

삭제는 confirm=true가 필요하고, 삭제 방지는 MCP로 끌 수 없습니다.

1 토큰 발급

포털에서 개인 액세스 토큰 만들기

토큰은 내 계정의 열쇠입니다. 개발 도구(노트북)마다 하나씩 만들어 두면 관리가 쉽습니다.

  1. https://itda.rgrg.im 접속 → Google 로그인
  2. 오른쪽 위 🔌 MCP 연결 클릭
  3. 토큰 이름 입력 (예: macbook-claude) → 발급
  4. 표시된 omcp_… 토큰 복사

⚠️ 한 번만 보여 줍니다

창을 닫으면 다시 볼 수 없습니다. 잃어버리면 새로 발급하세요.

🧹 폐기

같은 창의 목록에서 폐기를 누르면 즉시 끊깁니다. 마지막 사용 시각도 보입니다.

🔒 보관

토큰은 비밀번호처럼 다루세요. 저장소·채팅에 올리지 마세요. 계정당 최대 10개.

2 개발 도구 연결

itda MCP 서버 등록

포털의 🔌 MCP 연결 창에는 토큰이 채워진 명령이 그대로 나옵니다. 복사해서 실행하면 끝입니다.

Claude Code (터미널)

claude mcp add --transport http itda \
  https://itda.rgrg.im/mcp \
  --header "Authorization: Bearer omcp_..."

등록 후 Claude Code에서 /mcp로 연결 상태를 확인하고, "itda whoami 해줘"라고 물어보면 내 계정이 나옵니다.

Cursor · 기타 (mcp.json)

{
  "mcpServers": {
    "itda": {
      "url": "https://itda.rgrg.im/mcp",
      "headers": {
        "Authorization": "Bearer omcp_..."
      }
    }
  }
}
3 이미지 준비

내 PC에서 빌드해서 내부 registry에 push

"registry 정보 알려줘"라고 하면 MCP get_registry_info가 아래 명령을 내 계정 이름에 맞춰 만들어 줍니다.

# 최초 1회: HTTP registry 허용 (Docker Desktop → Settings → Docker Engine)
{ "insecure-registries": ["20.20.6.248:5000"] }

# 클러스터는 x86(amd64) — Apple Silicon이면 --platform 필수
docker build --platform linux/amd64 \
  -t 20.20.6.248:5000/jslee-myapp:v1 .

docker push 20.20.6.248:5000/jslee-myapp:v1

📛 이름 앞에 계정명

registry는 모두가 같이 씁니다. 계정명-앱이름으로 붙여야 다른 사람 이미지와 겹치지 않습니다.

🌐 사내망 · VPN

push는 사내망에서만 됩니다. 외부 도메인으로는 push할 수 없습니다.

🔑 비밀값은 이미지에 넣지 않기

API 키·비밀번호는 시크릿으로 주입합니다 (12쪽).

4 배포

"배포해줘"라고 말하기

AI 도구가 deploy_image를 호출합니다. 같은 이름으로 다시 부르면 내 서비스를 새 설정으로 교체합니다.

20.20.6.248:5000/jslee-myapp:v1 이미지를 jslee-myapp으로 배포해줘. PORT=8080 환경변수 넣고, /data는 재시작해도 유지되게.
deploy_image배포 완료 · node-b · 복제본 1
주소: https://itda.rgrg.im/jslee-myapp/
// deploy_image 인자
{
  "name": "jslee-myapp",
  "image": "20.20.6.248:5000/jslee-myapp:v1",
  "env": { "PORT": "8080" },
  "persistent_paths": ["/data"],
  "secret_refs": [{ "secret_id": "…", "env_name": "DB_PASSWORD" }],
  "memory": "512m", "cpu": "0.5",
  "replicas": 1
}

주소는 itda.rgrg.im/서비스명/ 경로 방식입니다. 앱은 컨테이너의 80번 포트에서 응답해야 하고, CSS·JS는 상대 경로로 불러와야 합니다.

Data

재시작해도 데이터가 남게 — persistent_paths

컨테이너는 재시작·업데이트 때마다 새로 만들어집니다. 지정한 경로만 데이터가 유지됩니다.

이렇게 동작합니다

  • 경로마다 관리형 볼륨이 만들어져 연결됩니다.
  • 서비스는 데이터가 있는 한 노드에 고정되고 복제본은 1개입니다.
  • 재시작 · 이미지 업데이트 · 다시 배포 · 자동 복구 모두 같은 노드, 같은 데이터로 올라옵니다.
  • 포털에서 만든 PostgreSQL·MySQL은 자동으로 적용됩니다.

삭제할 때

  • delete_service는 기본으로 데이터를 남깁니다 (어느 노드에 남았는지 알려 줌).
  • 데이터까지 지우려면 purge_data=true — 되돌릴 수 없습니다.
  • list_volumes로 내 저장소와 노드를 확인합니다.

주의 노드 하나의 디스크에 있으므로 그 노드가 멈추면 서비스도 멈춥니다. 중요한 데이터는 따로 백업하세요.

Operate

업데이트 · 스케일 · 재시작 · 삭제

새 버전을 push한 뒤 한 문장이면 됩니다.

update_image

새 태그로 교체하거나, 태그를 비우면 같은 태그를 다시 받아 재시작합니다.

scale_service

복제본 수 0~10 (0 = 중지). 영구 저장소가 있으면 1까지.

restart_service

모두 내렸다가 같은 수로 다시 올립니다. 환경변수·볼륨은 그대로입니다.

delete_service

confirm=true 필수. 🛡 삭제 방지가 켜져 있으면 거부됩니다.

jslee-myapp v2 push했어. 업데이트해줘
update_image20.20.6.248:5000/jslee-myapp:v2 로 교체했습니다.
트래픽 많으니 3개로 늘려줘
scale_service복제본 1 → 3 (node-b, node-c, master)

Safety

안심하고 써도 되는 이유

👤 내 서비스만

토큰·포털 모두 소유자만 수정할 수 있습니다. 다른 사람과 같은 이름으로 배포하거나, 다른 사람이 쓰는 이미지를 덮어쓰는 것도 막혀 있습니다.

🛡 삭제 방지

켜 두면 포털·관리 콘솔·MCP 어디서도 서비스와 컨테이너를 지울 수 없습니다. 해제는 로그인한 브라우저에서 소유자만 가능합니다.

🌐 공유는 선택

공유를 켠 서비스만 로그인 없이 포털 첫 화면에 보입니다. 환경변수·시크릿은 절대 공개되지 않습니다.

📝 감사 로그

배포·삭제·컨테이너 명령 실행·보호 설정 변경이 모두 기록됩니다.

🧱 서버 경로 연결 금지

일반 사용자는 서버 디렉터리·docker.sock을 컨테이너에 연결할 수 없습니다. 데이터는 persistent_paths로만.
